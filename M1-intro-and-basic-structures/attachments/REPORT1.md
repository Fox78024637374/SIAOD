## 2. Аналитические оценки (худший случай)

- **`array_sum` — Θ(N).** Один цикл: N сложений, каждое O(1).  
  `T(N) = N·c₁ + c₀`, значит `c₁·N ≤ T(N) ≤ (c₁+c₀)·N` для `N ≥ 1`.

- **`array_max` — Θ(N).** `N−1` сравнений, каждое O(1).  
  `T(N) = (N−1)·c₁ + c₀ = Θ(N)`.

- **`count_equal_pairs` — Θ(N²).** Двойной цикл:  
  `Σ_{i=0}^{N−1}(N−1−i) = N(N−1)/2` сравнений.  
  `T(N) = (N(N−1)/2)·c₁ + c₀ = Θ(N²)`.  
  Число сравнений не зависит от значений — всегда `N(N−1)/2`.

- **`binary_pow` — Θ(log N).** N содержит `⌊log₂ N⌋ + 1` бит, на каждый бит одна итерация `while`, внутри O(1) умножений по модулю.  
  `T(N) = (⌊log₂ N⌋ + 1)·c₁ + c₀ = Θ(log N)`.

**Почему Θ, а не только O.** Число операций не зависит от значений входа, поэтому нижняя и верхняя границы совпадают с точностью до константы. Дополнительная память — O(1).

## 4. Сопоставление теории и замеров (log-log)

| Алгоритм | Наклон | Теория | Отклонение |
| --- | ---: | ---: | ---: |
| `array_sum` | 0.938 | 1 | −6.2 % |
| `array_max` | 1.025 | 1 | +2.5 % |
| `count_equal_pairs` | 1.978 | 2 | −1.1 % |

**Объяснение расхождений.**

- **`array_sum` (0.938):** на `n = 1 000` удельная стоимость 27 нс, на `100 000` — 22 нс. Фиксированные накладные (вызов, инициализация) на малых `n` завышают левую точку, наклон уходит ниже 1.
- **`array_max` (1.025):** на `30 000` удельная минимальна (18.2 нс), на `100 000` растёт до 23.2 нс (выход за L2), правая точка поднимается, наклон выше 1.
- **`count_equal_pairs` (1.978):** рабочее время `10⁰–10¹` с, доминирует сам цикл, накладные малы. Отклонение −1.1 % — шум CPython.

**Оценка константы `c₁` (удельная стоимость).**  
`array_sum` ≈ 22 нс/элемент — это одна итерация `for … += …` в CPython 3.12 (`BINARY_OP(+)` с созданием нового `int`).  
`array_max` ≈ 18–23 нс — `COMPARE_OP(>)` дешевле (не создаёт объект).  
`count_equal_pairs` ≈ 30 нс/сравнение — дороже в 1.4× из-за двух индексаций `a[j]` на итерацию.

## 5. Особенности замера `binary_pow`

**Почему не log-log.**  
`t ≈ a + b·log₂ n`. В логарифмических осях `log t ≈ log(a + b·log₂ n)` — не прямая, наклон → 0 при больших `n`. Показатель степени восстановить нельзя. Регрессия по 5 точкам (в мкс): `t ≈ 0.055 + 0.121·log₂ n`, `R² = 0.996`. Постоянный член — цена вызова, коэффициент — цена одной итерации.

**Почему по модулю.**  
Без `mod` при `n = 10⁷` число `3^(10⁷)` содержит ≈ 4.77 млн десятичных знаков. Время определяется не числом итераций, а стоимостью умножения длинных чисел (`O(d^1.585)` у CPython). С `POW_MOD` после каждого умножения выполняется `% mod`, все операнды `< mod` (≈ O(1)), время одной итерации — константа.

**Важно:** медленная операция на длинных числах — умножение, а не сложение (сложение линейно по длине, умножение — суперлинейно).

## 6. Верификация

### 6.1. Граничные случаи

- `array_sum([]) == 0`, `array_sum([-3]) == -3`, `array_sum([7]) == 7`.
- `array_max([42]) == 42`; `array_max([])` → `ValueError` (инвариант «массив непуст»).
- `array_max([9,9,9,9]) == 9` (все равны).
- `array_max([-5,-1,-3]) == -1`.
- `count_equal_pairs([]) == 0`, `[7] → 0`, `[5,5,5] → 3`, `[5]*7 → 21` (`C(7,2)`).
- `binary_pow(2,0) == 1`, `binary_pow(2,0,mod=1) == 0`, `binary_pow(0,5,mod=97) == 0`.

### 6.2. Сверка с эталоном

- `array_sum(a) == sum(a)`, `array_max(a) == max(a)` — 200 случайных массивов длины 1…60, `a[i] ∈ [-50, 50]`.
- `binary_pow(x, n, mod=POW_MOD) == pow(x, n, POW_MOD)` — 200 пар `(x, n)`, `x ∈ [2, 50]`, `n ∈ [0, 64]`.

### 6.3. Инварианты

- Частотный: `count_equal_pairs(a) == Σᵢ cᵢ(cᵢ−1)/2`, где `cᵢ` — частота. 200 массивов длины 0…40, значения из `[-3, 3]`.
- Уникальность: на массиве различных элементов = 0.
- `binary_pow`: `0 ≤ результат < mod`.
- `array_max`: результат ∈ `a` и ≥ любого элемента.
- Аддитивность `array_sum`: `array_sum(a+b) == array_sum(a) + array_sum(b)`.
- `array_max ≥ mean`: `array_max(a) ≥ array_sum(a)/len(a)`.
