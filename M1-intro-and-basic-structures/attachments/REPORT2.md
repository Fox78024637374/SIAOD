## 2. Аналитические оценки (худший случай)

### 2.1. Рекурсия

| Функция | Время | Стек | Обоснование |
| --- | --- | --- | --- |
| `factorial(n)` | `Θ(n)` | `Θ(n)` | `n` вызовов, `O(1)` на вызов |
| `fib_naive(n)` | `Θ(φⁿ)`, `φ ≈ 1.618` | `Θ(n)` | `T(n)=T(n−1)+T(n−2)+O(1)` |
| `fib_memo(n)` | `Θ(n)` | `Θ(n)` | каждая подзадача один раз |
| `hanoi(n)` | `Θ(2ⁿ)` | `Θ(n)` | `T(n)=2T(n−1)+O(1)` |

- `fib_naive`: характеристическое уравнение `x² = x + 1` ⇒ `φ = (1+√5)/2`, `T(n) = Θ(φⁿ)`, точное число вызовов `2·F(n+1) − 1`.
- `hanoi`: развёртка `T(n) = 2T(n−1)+1 = … = 2ⁿ − 1`.
- `fib_memo`: `n+1` уникальных подзадач, каждая `O(1)`, повторный вход — `O(1)`, значит `Θ(n)`.

Мастер-теорема неприменима ни к одной из четырёх функций: у `fib_naive` и `hanoi` — вычитание в аргументе, у `factorial`/`fib_memo` рекуррентность линейная. Примеры трёх случаев мастер-теоремы для сравнения: `2T(n/2)+O(1)=Θ(n)`; `2T(n/2)+O(n)=Θ(n log n)`; `2T(n/2)+O(n²)=Θ(n²)`.

### 2.2. Структуры данных

| Метод | Время | Обоснование |
| --- | --- | --- |
| `DynamicArray._grow` | `Θ(n)` | перенос всех элементов |
| `DynamicArray.append` | `Θ(1)` амортизированно | метод учёта, § 4 |
| `DynamicArray.pop` | `Θ(1)` аморт. | со сжатием при `size ≤ capacity/4` |
| `DynamicArray.get/set` | `Θ(1)` | прямой индекс |
| `Stack.push/pop/peek` | `Θ(1)` аморт. | делегируют `DynamicArray` |
| `Deque.push_*/pop_*` | `Θ(1)` в худшем случае | перевязка указателей |

**Ключевое различие:** у `DynamicArray.append` — амортизированная оценка (отдельный `append` при росте `Θ(n)`, средняя `Θ(1)`); у `Deque` — в худшем случае (любая операция в любой момент `O(1)`).

## 3. Рекурсия: наивная vs мемоизация

| n | F(n) | `fib_naive` | `fib_memo` | `2·F(n+1)−1` | `2n−1` |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 5 | 5 | 15 | 9 | 15 | 9 |
| 10 | 55 | 177 | 19 | 177 | 19 |
| 15 | 610 | 1 973 | 29 | 1 973 | 29 |
| 20 | 6 765 | 21 891 | 39 | 21 891 | 39 |
| 25 | 75 025 | 242 785 | 49 | 242 785 | 49 |
| 30 | 832 040 | 2 692 537 | 59 | 2 692 537 | 59 |

Формулы числа вызовов (совпадают со счётчиком `CALLS`):

- `fib_naive`: `calls(n) = 2·F(n+1) − 1` (следует из `c(n) = c(n−1) + c(n−2) + 1`, `c(0)=c(1)=1`). Рост `Θ(φⁿ)`.
- `fib_memo`: `calls(n) = 2n − 1` — по одному «первому» вызову на каждую подзадачу плюс повторные попадания.

Рост наивной при `n: 25 → 30` — в `2692537/242785 ≈ 11.1` раза (≈ `φ⁵`), у мемоизированной — `+10` вызовов.

`hanoi(n)` — ровно `2ⁿ − 1` ходов, при `n = 20` — `1 048 575`.

**Про базовое условие.** Без него — `RecursionError` (стек `sys.getrecursionlimit() = 1000`). Для `fib_naive(30)` глубина стека всего 30, а вызовов 2.7 млн: стек вызовов и число вызовов — разные величины. Наивная рекурсия дорога ветвлением, а не глубиной.

Стоимость `DynamicArray.append` ≈ `1.3–1.6·10⁻⁷` с, у `list.append` ≈ `3·10⁻⁸` с. Отношение ≈ `4–5×` — постоянный множитель (C-цикл роста у `list`), не асимптотика.

### 4.2. Банковский метод (основной)

Назначим каждому `append` амортизированную стоимость 3 монеты.

- **Без роста.** Фактическая 1. В банк 2 монеты.
- **С ростом `k → 2k`.** Фактическая `k+1` (перенос `k` + запись). Из банка уходит `k − 2`.

Между двумя ростами — ровно `k−1` операций без роста, каждая откладывает 2 монеты ⇒ к моменту роста в банке `2(k−1)`. Росту нужно `k−2`. При `k ≥ 3`: `2(k−1) ≥ k − 2`. Инвариант «банк ≥ 0» сохранён. Суммарная амортизированная стоимость `n` операций ≤ `3n`, средняя — `3 = O(1)`.

### 4.3. Сопоставление с замером

`(n + copies)/n` — это `T(n)/n`, агрегатная амортизированная стоимость. Диапазон `[2.000, 2.999]` согласуется с теорией:

| Случай | `copies(n)` | `T(n)` | `T(n)/n →` |
| --- | ---: | ---: | ---: |
| `n = 2^k` (перед ростом) | `n − 4` | `2n − 4` | → 2 |
| `n = 2^k + 1` (сразу после) | `2n − 6` | `3n − 6` | → 3 |

В таблице § 4.1: `n = 8 192 = 2¹³ → 2.000`, `n = 8 193 = 2¹³ + 1 → 2.999`.

**Почему у `2^k` и `2^k + 1` разница почти 1.** При `n = 2^k` последнее удвоение уже оплачено, следующего нет. При `n = 2^k+1` в `copies` только что добавилось `2^k` переносов. Разница ≈ `2^k/n ≈ 1`.

**Альтернативные методы (для полноты).** Агрегатный даёт `T(n) < 3n` через геометрическую прогрессию `4+8+…+2^k < 2n`. Потенциальный с `Φ = 2·size − capacity` даёт ровно 3 на операцию: без роста `1 + 2 = 3`, с ростом `(k+1) + (2−k) = 3`. Все три метода — `O(1)`.

### 4.4. Сравнение роста ×2 и ×1.5

| α | Аморт. стоимость `α/(α−1)` | Перерасход памяти |
| ---: | ---: | ---: |
| 1.5 | 3 | 33 % |
| 2 | 2 | 50 % |
| 3 | 1.5 | 67 % |

Компромисс: `α=2` — лучше амортизация, дороже память. CPython `list` — `α ≈ 1.125`, C++ `std::vector` — `α = 2`, Java `ArrayList` — `α = 1.5`.

### 5.3. Сопоставление с теорией

Ожидалось: `list.insert(0,x)` и `list.pop(0)` — `Θ(n)`, наклон ≈ 1; `deque`/`Deque` — `Θ(1)`, наклон ≈ 0. Замеры: `0.96`, `1.01`, `0.02`, `−0.00` — совпадение с точностью до шума.

При `n: 1 000 → 100 000` время `list.insert(0,x)` выросло в 80 раз; для `deque`/`Deque` — не изменилось.

**Почему `list` медленный.** `list` — непрерывный массив, `insert(0, x)` и `pop(0)` сдвигают все `n` указателей — `Θ(n)`.

**Почему дек быстрый.** `Deque` — двусвязный список: `push_front` создаёт узел, перевязывает 2 указателя — `O(1)` в худшем случае. `collections.deque` — блочный массив, `appendleft` переключает указатель на предыдущий блок — `O(1)`.

### 5.4. Накладные расходы `Deque`

Наш `Deque` ≈ в 10 раз медленнее `collections.deque`. Причины: аллокация `_Node` на каждый `push`, атрибутный доступ `node.prev`/`node.next` (`LOAD_ATTR`, ~10–20 нс), память на узел: ≈ 56 байт (`_Node` с 3 слотами) против ≈ 8 байт на элемент в `collections.deque`. При `n = 100 000` — 5.6 МБ против 0.8 МБ, разница ≈ 7×.

Именно поэтому `collections.deque` реализован на блочном массиве, а не на классическом списке.

## 7. Верификация

### 7.0. Инварианты

- `DynamicArray`: `0 ≤ size ≤ capacity`; `capacity = 4` при `size ≤ 4`; для `size > 4` — `capacity = 2^m`, `size > 2^(m−1)`; сжатие — только при `size ≤ capacity/4`, не ниже `INITIAL_CAPACITY`.
- `Stack`: LIFO.
- `Deque`: FIFO с каждого конца независимо.
- Исключения: `pop`/`peek`/`get`/`set` на пустой или с неверным индексом — `IndexError`; `len` при исключении не меняется.
- Все свои проверки — через `expect()`/`SelfCheckError`, не `assert`; не отключаются при `python -O` (проверено запуском `python -O …starter.py`).

### 7.1. Рекурсия

- `factorial(n) == math.factorial(n)` для `n = 0…20`.
- `fib_naive(n) == F(n)` для `n = 0…20`; число вызовов `≥ F(20)`.
- `fib_memo(n) == F(n)` для `n ∈ {0,1,2,10,30,90}`; вызовов `≤ 2n+1`.
- `hanoi(n)` для `n ∈ {0,1,2,3,6,7}` с проигрыванием ходов: `2ⁿ−1` ходов, все диски на `dst`, больший на меньший не кладётся.
- Свой инвариант: `calls_fib_naive(n) == 2·F(n+1) − 1` на `n ∈ {0,1,2,5,10,15,20}`.
- Свой инвариант: `calls_fib_memo(n) == 2n − 1` на всех `n` из `FIB_NS`.

### 7.2. `DynamicArray`

- Пустой: `len=0`, `capacity=INITIAL_CAPACITY`; `get`/`set`/`pop` → `IndexError`.
- Границы ёмкости `4,8,16,32,64` на 100 `append`: `capacity == expected_capacity(size)`, `copies == expected_copies(size)`.
- `get`/`set` по всем индексам `0…99`; неверные (`100`, `capacity−1`, `capacity`, `−1`, `−100`) → `IndexError`.
- `pop` до пустого и повторное наполнение; сжатие — только при `size ≤ capacity/4` и не ниже 4.
- Свой инвариант: `copies == expected_copies(n)` для `n=1…100`.

### 7.3. `Stack` и `Deque`

- `Stack`: LIFO через две границы ёмкости; `pop`/`peek` пустого → `IndexError`; 3 000 случайных операций сверены с `list`.
- `Deque`: все 16 сочетаний `push_* × pop_*` с повторным наполнением; `pop_*` пустого → `IndexError`; 5 000 случайных операций сверены с `collections.deque`.
- Свой инвариант: `Deque` с `push_front`/`push_back` извлекает LIFO с каждого конца независимо.
